API Routes

Status: done

The app exposes a small set of Next.js App Router route handlers. Game state persistence is backed by Upstash Redis (KV). Game state lives in the Three.js render loop at 60fps, with React state mirroring UI/HUD via the useGameState hook, and persistence driven through the useGamePersistence hook. Auto-save fires on resource collection, selling, buying, and station repair.

GET /api/game/[id]

Loads saved game state for the given save id. Reads from KV under the key prefix game:, parses the stored JSON, and validates it against GameStateSchema. Returns the state as JSON when present and valid. Returns HTTP 404 with { "error": "not found" } when no saved state exists for the id.

PUT /api/game/[id]

Saves game state for the given save id. The request body is validated against GameStateSchema. On a validation failure it returns HTTP 400 with { "error": "invalid state" } and the flattened validation details. On a successful save it returns { "ok": true }. When the KV store is unavailable and the write fails, it returns HTTP 503 with { "error": "storage unavailable" }.

GET /api/health

Health check endpoint. Returns { "status": "ok", "timestamp": <ms> } where the timestamp is the current epoch time in milliseconds.

GET /api/version

Reports the current build version. Returns { "version": <value>, "timestamp": <ms> }. The version is read from the NEXT_PUBLIC_APP_VERSION environment variable, falling back to "dev" when unset.

POST /api/feedback

Submits player feedback. The request body is validated against FeedbackSchema. On a validation failure it returns HTTP 400 with { "error": "invalid feedback" } and the flattened validation details. On success the feedback is persisted to KV under the key feedback:<timestamp> and the handler returns { "ok": true }. Persistence is best effort: if the KV write throws, the error is logged and the request still succeeds. The feedback FAB (floating action button) on the pause overlay POSTs the player's message to this route.
